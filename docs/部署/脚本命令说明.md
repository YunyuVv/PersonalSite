# 脚本命令说明（package.json scripts）

> 适用项目：清正个人站点（Next.js 16 App Router + React 19）
> 作用域：`pnpm run <命令>` 或 `npm run <命令>`

本项目有三条部署/预览路线：**本地开发**、**Node SSR + Docker（主链路）**、**纯静态导出**、**Cloudflare Workers**。下面按 `package.json` 中的脚本逐一说明。

---

## 1. `dev` — 本地开发服务器
```bash
pnpm dev        # 等价于 next dev -p 12002
```
- 启动 Next.js 开发模式，监听 `http://localhost:12002`。
- 改动源码即时热更新（HMR），适合编码调试。
- 走 SSR 链路：后台 `/admin` 实时改配置可正常生效（POST 鉴权依赖服务端）。
- ⚠️ 若端口被占用（如之前遗留的进程），先 `lsof -nP -iTCP:12002 -sTCP:LISTEN` 查 PID 再 `kill <pid>`。

---

## 2. `build` — 生产构建（SSR + standalone，主链路）
```bash
pnpm build      # 等价于 next build
```
- 默认产出 `.next/standalone/server.js`（Node SSR 可执行产物），配合 `Dockerfile` 打包镜像。
- 启用 `output: "standalone"`，支持后台 `/api/admin/config` 运行时实时改配置。
- 构建前需清空本机可能设有的 `NODE_OPTIONS`（如 `--use-system-ca`），否则 Turbopack 报 `ERR_WORKER_INVALID_EXEC_ARGV`：
  ```bash
  NODE_OPTIONS= pnpm build
  ```

---

## 3. `build:static` — 纯静态导出（零后端）
```bash
pnpm build:static   # 等价于 node scripts/build-static.mjs
```
- 产出 `out/` 目录（纯静态 HTML/JS/CSS），可直接丢到任意静态托管（Cloudflare Pages / GitHub Pages / 腾讯云 COS 中国香港 + CDN）。
- 内部流程（`scripts/build-static.mjs`）：构建前把 API 路由 `dynamic` 临时改为 `force-static` 以满足导出要求 → 跑 `next build`（此时 `output: "export"`）→ 构建后还原为 `force-dynamic`，保证 SSR 主链路实时鉴权不受影响。
- 配置在构建期**烘焙进 HTML**，改配置需重新 `build:static` 并重新上传 `out/`；后台实时编辑在无服务端时不可用。
- 图片优化自动关闭（`images.unoptimized`），因为静态托管没有 Next 图片服务。

---

##  ̄4. `serve:static` — 本地预览静态产物
```bash
pnpm serve:static   # 等价于 npx serve out
```
- 用 `serve` 在本地起一个静态服务器，预览 `out/` 目录（首次会自动下载 `serve`）。
- 仅用于本地查看静态导出效果，不是生产服务方式。

---

## 5. `start` — 启动生产服务器
```bash
pnpm start      # 等价于 next start
```
- 启动 `build` 产出的生产版本（`next start` → 内部托管 `.next`）。
- 注意：Docker 实际运行的是 `node server.js`（standalone），`next start` 是等价/备用的本地启动方式。
- 默认端口 3000，可用 `PORT=xxxx pnpm start` 覆盖。

---

## 6. `lint` — 代码检查
```bash
pnpm lint       # 等价于 eslint
```
- 按 `eslint.config.mjs` 规则检查代码风格与潜在问题。
- 建议在提交/构建前运行，提前发现类型与规范问题。

---

## 7. `build:worker` — Cloudflare Workers 构建
```bash
pnpm build:worker   # 等价于 opennextjs-cloudflare build
```
- 通过 `@opennextjs/cloudflare` 把 Next.js 构建为目标到 Cloudflare Workers 的产物（`.open-next/`）。
- 适合「免备案 + 全球 CDN」的边缘部署，但后台实时编辑依赖 Workers + KV，本项目的 `/admin` 实时方案未接入该路线。

---

## 8. `preview:worker` — 本地预览 Workers
```bash
pnpm preview:worker   # opennextjs-cloudflare build && opennextjs-cloudflare preview
```
- 先构建 Worker，再用 wrangler 本地预览（Miniflare），验证 Worker 产物是否符合预期。

---

## 9. `deploy:worker` — 部署到 Cloudflare
```bash
pnpm deploy:worker   # opennextjs-cloudflare build && opennextjs-cloudflare deploy
```
- 构建并一键部署到 Cloudflare Workers（需先 `npx wrangler login` 登录）。
- 适合作为「免备案 + 国内可访问」的边缘托管方案（Cloudflare 国内访问略慢于中国香港节点）。
