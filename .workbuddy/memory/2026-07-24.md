## Cloudflare 部署方案落地（PersonalSite / Next.js 16）

- 决策：**部署到 Cloudflare Workers（OpenNext），不走 Pages**。理由：`@cloudflare/next-on-pages` 已退役且不支持 Next 16；Pages 平台进入维护模式；OpenNext `@opennextjs/cloudflare` 支持 Next 16.2.3+（本项目 16.2.11）。
- 项目性质：纯静态展示站（无 API/middleware/server actions/next-image/next-headers），OpenNext 转 Worker+静态资源完全兼容，保留后续加 SSR/API 能力。
- 已加文件/配置：`wrangler.jsonc`（name=personal-site, main=.open-next/worker.js, assets, nodejs_compat）、`open-next.config.ts`（静态资源缓存，无需 KV）、`package.json` 脚本 `build:worker`/`preview:worker`/`deploy:worker`、`devDependencies`(@opennextjs/cloudflare, wrangler)、`.gitignore` 忽略 `.open-next/`。
- **关键依赖坑（必须进 lockfile）**：`@opennextjs/cloudflare→glob@12→minimatch@10→brace-expansion@5` 按 ESM 命名导入 `balanced-match`，但 pnpm 在该链解析成 CJS 版 1.0.2，构建报 `Named export 'balanced' not found`。修复：`pnpm.overrides` 强制 `balanced-match: 4.0.4`（同时提供 ESM/CJS 命名导出）。不修则 Cloudflare 网页端构建同样失败。
- 本地沙箱 `NODE_OPTIONS=--use-system-ca` 会让 Next16 Turbopack Worker 报错，清掉即可（`NODE_OPTIONS= pnpm run build:worker`）；Cloudflare 环境无此问题。
- GitHub 联动部署（Workers Builds）：**Build command 必须手动填 `pnpm run build:worker`**；**Deploy command 保持默认 `npx wrangler deploy`**；包管理器自动识别 pnpm。
- 已验证 `opennextjs-cloudflare build` 成功产出 `.open-next/worker.js` + 静态资源（全部路由为 Static）。
- 文档：见 `docs/deploy-cloudflare.md`。

## 构建失败修复：`pnpm-workspace.yaml` 缺 `packages` 字段
- 现象：Cloudflare Workers Builds 在 `pnpm install --frozen-lockfile` 阶段报 `ERROR packages field missing or empty`，安装即中断（未到 build 步骤）。
- 根因：仓库根有 `pnpm-workspace.yaml` 但只有 `ignoredBuiltDependencies`（sharp/unrs-resolver）而无 `packages`。Cloudflare 的 pnpm@10.11.1 把含该文件的项目当 workspace 处理、要求 `packages` 字段；本地 pnpm@10.20.0 更宽松故未报错。
- 修复：补 `packages: ["."]`（根目录即 workspace 包），与现有 lockfile（`importers: '.'`，lockfileVersion 9.0）吻合，无需重新生成 lockfile。保留 `ignoredBuiltDependencies` 跳过原生二进制构建。
- 已 `pnpm install --frozen-lockfile` 本地验证通过（EXIT=0, Lockfile up to date）。提交 `62202f2` 已 push，Cloudflare 会随 push 自动重建。
